# ProjectOrchestrator Adapter 版本同步与自动化 - 规范概览

## 📋 执行摘要

本规范定义了一个全面的解决方案，用于解决 ProjectOrchestrator Skill 项目中的版本管理问题。问题是：不同 IDE（Cursor、Cline、Claude、Kiro、Antigravity 等）的适配器文件已与权威的 `skill.md` 不同步，导致维护困难。

**解决方案**：实现自动化版本追踪、适配器生成和 CI/CD 验证，确保所有组件的一致性。

---

## 🎯 主要可交付物

### 1. **标准化文件命名**
- 重命名 `templates/ai/PRD.md` → `requirements.md`
- 更新所有 9+ 个适配器文件中的引用
- 实现 100% 的命名一致性

### 2. **英文优先的适配器**
- 将所有中文内容翻译为英文
- 保持双语触发关键词（用户方便）
- 为未来语言支持创建 i18n 框架

### 3. **自动化适配器生成**
- Python 工具（`adapter-generator.py`）自动从 `skill.md` 生成适配器
- 自动生成 80%+ 的适配器内容
- 减少手工编辑 60%

### 4. **版本追踪系统**
- 集中的 `.ai/SKILL_VERSION.md` 文件
- 发布说明、同步检查清单、回滚说明
- 自动防止版本漂移

### 5. **CI/CD 自动化**
- GitHub Actions 工作流进行版本验证
- Pre-commit hooks 进行本地验证
- 零手工同步需求

### 6. **全面文档**
- `ADAPTER_MAINTENANCE.md` - 维护流程
- `tools/README.md` - 生成器用户指南
- 发布说明和迁移指南

## ❓ 常见问题

**Q：如果我们需要跳过某些阶段怎么办？**

答：不推荐。每个阶段建立在前一个阶段之上。然而，如果需要，第 5 阶段（文档）可以延迟，但应在发布前完成。

**Q：我们能并行化更多任务吗？**

答：是的！任务 4-9 (英文化) 可以完全并行运行。任务 15-16 (CI/CD) 可以并行运行。见 `tasks.md` 了解并行化策略。

**Q：这要花多长时间？**

答：预计 59 小时总计（2-3 周 1 个开发者，或 1 周 2 个开发者并行工作）。

**Q：如果我们在实施中发现问题怎么办？**

答：更新规范！使用 EVOLUTION_PROPOSALS.md 模式：记录问题、提出解决方案、获得批准、然后实施。

**Q：我们能现在添加 i18n 支持吗？**

答：不。第 1 阶段创建 i18n 框架结构，但实际翻译推迟到未来阶段。这使第 1 阶段保持专注。

**Q：向后兼容性怎么样？**

答：设计确保使用 PRD.md 的旧项目仍然工作。添加贬低警告到初始化脚本。在移除前 2 个发布的贬低期。
